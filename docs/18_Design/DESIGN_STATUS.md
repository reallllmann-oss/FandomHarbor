## 11. Current Design Decisions

### Accepted From UX-01

UX-01 已确认以下设计基础：

- Fandom Harbor 的品牌方向是安静、可信、文学、私域、可治理的作品归档与阅读产品。
- 视觉方向应表达 quiet editorial、private archive、literary calm、precise metadata 和 long-form comfort。
- UX 原则以 Reader First、Content Hierarchy、Emotional Reading、Minimal Interaction 和 Premium Editorial Experience 为核心。
- 所有后续 UX Mission 必须避免普通 SaaS、论坛、博客、社交 feed、电商促销页和公开热度竞争的设计漂移。

### Accepted From UX-02

UX-02 已接受以下信息架构决策：

- Fandom Harbor 的体验架构应从页面集合转为任务空间：Entry、Discovery、Decision、Reading、Return、Creation。
- Archive 应承担发现和浏览；Library / History / Continue Reading 应承担私有回访。
- Work 是作品判断和阅读承诺点；Reading 是沉浸阅读空间。
- Studio 是作者创作归档工作台，不是普通后台 CMS。
- Author Profile 是公开作者身份和作品聚合，不是社交主页。
- 内容层级应以 Story Content 为 Primary，以 Author Identity、Category、Metadata 为 Secondary，以 Statistics、Tags、Interactions、Reader Return 为 Supporting。

### Accepted From UX-03

UX-03 已接受以下 Design System Intelligence 决策：

- Fandom Harbor 的设计语言应是 Quiet Editorial、Private Archive、Precise Metadata、Soft Authority。
- Typography 应同时支持文学阅读节奏和编辑式信息层级。
- Color System 应使用 semantic direction 表达情绪和状态，例如 Harbor Night、Paper Surface、Morning Light、Ink Stone、Tidal Teal、Lantern Amber、Safe Mooring、Red Signal；本阶段不锁定色值或 token。
- Layout 应围绕 Entry、Discovery、Decision、Reading、Return、Creation 六类任务空间建立不同节奏和密度。
- Component Philosophy 应先表达意图，再表达形态；Button、Card、Navigation、Content Block、Metadata 都服务阅读、归档和状态清晰。
- Reading Experience 是核心体验，应保护 prose focus、reading measure、chapter flow、distraction control 和 long reading stability。

### Accepted From UX-04

UX-04 已接受以下页面体验决策：

- Homepage 是私域文学归档的品牌入口和访问状态分流点，不是作品列表、营销页或公开社区首页。
- Archive 是 Discovery Space；Library / History / Continue Reading 属于私有回访概念。Archive / Library / Works / Shelf 的最终命名仍不在 UX-04 锁定。
- Work Detail 是故事判断和阅读入口页面，必须优先支持摘要理解、分级 / 预警、作者公开身份、元数据和章节入口。
- Reading Page 是最高优先级页面，必须保护正文焦点、长读节奏、章节流、情绪连续性和低干扰。
- Author Profile 是通过公开作品表达的创作者身份空间，不是个人资料卡、社交主页或粉丝主页。
- Studio 是作者创作、管理、发布和验证读者可见结果的工作空间，不是普通 CMS、增长后台或 Admin 控制台。
- 页面关系定义为 Homepage -> Discovery -> Story Decision -> Reading -> Return，以及 Author -> Creation -> Publishing -> Public Identity。

### Accepted From UX-05

UX-05 已接受以下 Homepage Visual Direction 决策：

- Homepage 推荐视觉方向为 Quiet Editorial Harbor。
- 方案 1 的留白、编辑感和品牌气质可作为主要参考，但不复制 issue / subscription 模型。
- 方案 3 的作品展示方式可作为故事预览逻辑参考，但 Homepage 不能变成作品列表。
- 方案 4 的稀疏导航结构可作为 intent-based navigation 参考，但不继承 retail / product hero 气质。
- 方案 5 的底部收束节奏可作为 quiet closing 参考，但不采用 newsletter conversion 作为主要关系。
- 方案 2 可作为阅读克制气质参考，但不采用极窄长卷首页结构。
- Homepage 应避免普通小说网、博客、杂志订阅页、零售首页、SaaS landing、CMS dashboard、公开排行榜和社交 feed。

### Accepted From UX-05B

UX-05B 已接受以下 Reading Visual Direction 决策：

- Reading Page 推荐视觉方向为 Private Literary Reading Space。
- Apple Books 仅作为抽象学习对象：学习安静阅读环境、聚焦排版和最小交互，不复制产品逻辑或 UI 形式。
- Reading Page 必须保留 Fandom Harbor 的文学温度、作者连接、故事氛围、私人阅读空间感和情绪连续性。

- Chapter transition 是情绪连续性的一部分，不只是上一章 / 下一章工具。

### Accepted From UX-05C

UX-05C 已接受以下 Archive Visual Direction 决策：

- Archive 推荐视觉方向为 Curated Story Discovery Space。
- Archive 是故事发现空间，不是小说列表、数据库浏览、分类目录、小说商城、排行榜、社交 feed 或 CMS 列表。
- Archive 应帮助读者通过标题、摘要、公开作者身份、分级、预警、分类、状态和标签发现适合当下的作品。
- Archive 与 Library / Shelf 分离：Archive 属于公开发现，Library / Shelf 属于私有回访和保存阅读连续性。
- Continue Reading 是直接恢复到已知阅读位置，不承担浏览、筛选或目录比较。
- Works 是上下文相关的对象标签，在 Reader 语境可指 published works，在 Author / Studio 语境可指作者管理对象；最终命名不在 UX-05C 锁定。
- Archive 信息密度应高于 Homepage 预览、低于论坛 / dashboard / CMS 密度。
- Story title、summary、public author identity、rating、warnings 是主要发现信号；tags、statistics、engagement signals 只能作为支持信息。
- Archive 必须与 Homepage 的 Quiet Editorial Harbor 和 Reading 的 Private Literary Reading Space 形成连续体验。

### Accepted From UX-05D

UX-05D 已接受以下 Author Visual Direction 决策：

- Author Profile 推荐视觉方向为 Literary Creator Identity Space。
- Author Profile 是 Fandom Harbor 的公开创作者身份空间，不是普通用户 Profile、社交主页、粉丝页、活动流、CMS 作者后台或作品商城。

- Author Profile 可以使用克制的作者上下文与可选视觉元素，但不得依赖头像式社交身份表达。
- Author Profile 必须与 Homepage 的 Quiet Editorial Harbor、Archive 的 Curated Story Discovery Space 和 Reading 的 Private Literary Reading Space 形成连续体验。

### Accepted From UX-05E

UX-05E 已接受以下 Studio Visual Direction 决策：

## 12. Current Visual Direction

Current Homepage visual direction: Quiet Editorial Harbor

Homepage definition:

Homepage should feel like entering a protected literary archive: calm, editorial, private, text-led and trustworthy. It should establish brand threshold first, then route users by access and intent, then offer restrained story / archive preview and quiet closing.

Current Reading visual direction: Private Literary Reading Space

Reading definition:

Reading Page should feel like a quiet, private, continuous story space: Apple Books-like in calm focus, but warmer and more literary through Fandom Harbor's author connection, story atmosphere and archive context.

Current Archive visual direction: Curated Story Discovery Space

Archive definition:

Archive should feel like a calm, editorial, metadata-supported story discovery space. It helps readers explore published works by story fit, author context and reading boundaries without marketplace, ranking, feed or CMS pressure.

Current Author visual direction: Literary Creator Identity Space

Author definition:

Author Profile should feel like a quiet, literary public creator identity space. It helps readers understand a public pen name through creator context and published works, without social profile, follower economy, fan hub or CMS backend patterns.

Current Studio visual direction: Protected Creator Workspace

Studio definition:
