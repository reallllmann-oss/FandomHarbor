# Fandom Harbor Product and Engineering Principles

Status: Accepted in Phase 0.5; reaffirmed during Phase 0.6 review

## 1. Reading First

阅读体验优先。页面层级、性能、排版、移动端手感、预警展示和章节导航首先服务于读者持续、舒适地阅读，而不是鼓励点击和停留时长。

## 2. Archive First

作品归档优先。作品、作者笔名、章节、系列、标签、版本和可检索元数据必须稳定、可治理、可恢复。产品不建立信息流式社交平台。

## 3. Invitation First

邀请码是信任链，不只是入口钥匙。邀请码需要来源、有效期、使用次数、撤销和邀请链记录；但邀请永远不能自动授予 Author、Admin 或 Super Admin。

## 4. Trust First

举报、评论、邀请和权限操作都必须可追踪。追踪用于责任、恢复和反滥用，不意味着无限收集个人数据；敏感记录实行最小访问和明确保留期限。

## 5. Documentation First

文档先于代码。经过批准的 `.ai/` 与 `docs/` 是项目唯一可信来源；会议聊天、代码注释和临时原型不能暗中改变产品行为。

## 6. Mobile First

移动端不是桌面版的适配项，而是核心体验。阅读、发现和作者核心流程从小屏、触控、弱网络和系统字体缩放开始设计。

## 7. Accessibility First

阅读页、表单和后台都必须考虑可访问性。键盘、焦点、屏幕阅读器、对比度、缩放、触控目标和减少动态效果属于验收条件，不是发布后的补丁。

## 8. Security First

权限必须前后端双重验证，不能只依赖前端。前端负责安全清晰的展示与阻止误操作；真正的权限强制由可信服务端校验与 PostgreSQL RLS/授权共同完成。

## 9. Maintainability First

宁愿慢一点，也不要写难维护的代码。优先清晰边界、小步交付、严格类型、迁移、测试、审查和可回滚设计；拒绝为了短期速度制造长期隐患。

## 10. No Social Drift

禁止把产品做成微博、论坛、粉丝社区或私信平台。评论、Kudos、收藏和推荐只能服务作品与阅读，不演化为关注关系、动态流、粉丝排名、转发或私信网络。

## Decision filter

任何新功能都必须回答：它是否明显改善阅读、发布、归档治理、安全或项目可维护性？如果答案是否定或模糊，应当拒绝、缩小或延后。
