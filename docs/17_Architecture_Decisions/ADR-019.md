# ADR-019 — `works + chapters + articles` 内容领域模型

- Date: 2026-06-30
- Status: Accepted
- Owners/reviewers: Product Owner / Tech Lead
- Related .ai decisions: D-003, D-006, D-007, D-011, D-012, D-034
- Related requirements/risks: Phase 2 / Sprint 002A Content Domain Foundation

## Context

Fandom Harbor 同时需要承载可分章的小说/作品与不需要作品容器的独立文章。若把所有内容都塞入一张表，章节排序、作品级元数据和文章级生命周期会形成大量互斥字段；若把短文强制包装成单章作品，则独立文章的路由、管理和查询语义会被无意义的父容器污染。

本阶段只建立内容领域基础，不实现编辑器、Revision、社区互动、Storage 或公开署名系统。Phase 1 已建立 Membership 与 `role_grants`，内容权限必须复用这些事实源。

## Decision

1. `works` 保存可分章作品的稳定身份、元数据与发布生命周期；`chapters` 通过 `work_id` 归属作品，并在作品内保持唯一顺序和 slug。
2. `articles` 保存不需要作品容器的独立长文，拥有自己的正文与发布生命周期，不创建虚假的单章作品。
3. `content_categories` 是作品/文章的单选分类词表；`content_tags` 是共享的多选、可治理标签词表；`work_tags` 与 `article_tags` 明确维护多对多关系。
4. `works.slug` 与 `articles.slug` 分别在各自路由命名空间全局唯一；`chapters.slug` 只在所属作品内唯一；分类和标签 slug 在各自词表全局唯一。slug 强制使用小写 ASCII kebab-case，避免依赖大小写不敏感扩展。
5. `owner_user_id` 是私有授权字段，不是公开作者身份。列级 grant 不向普通内容读取暴露该字段；后续公开署名继续通过独立的 Pen Name / authorship 模型实现。
6. 访客仍不能读取归档正文。`published` 内容只对 active Membership 可读；拥有 Author 角色的所有者可管理自己的内容，Admin/Super Admin 可管理全部内容。所有判断复用 Phase 1 的 Membership 与 `role_grants`，不引入第二套权限表或 JWT 角色事实源。
7. 本阶段正文使用带 `schema_version` 的 JSON object 作为未来 TipTap 文档边界，但不实现编辑器、Revision、Diff 或 Restore。发布后修订仍必须在后续 Sprint 通过不可变 Revision 工作流完成。

## Consequences

### Positive

- 多章节作品与独立文章都拥有自然的数据模型和查询边界。
- 共享分类/标签避免重复词表，同时保留作品与文章独立生命周期。
- slug 冲突范围与路由范围一致，约束简单、可重建且不依赖新扩展。
- 私有账号所有权和未来公开笔名署名保持隔离。
- 内容 RLS 直接组合现有 Membership/Role Grant，撤销或暂停立即生效。

### Negative / trade-offs

- 作品和文章需要少量并行查询与映射代码，不能假装成完全相同的资源。
- 本阶段没有 Revision 表，已发布正文的编辑工作流尚未开放。
- `owner_user_id` 是过渡性的授权关系；公开协作署名与多笔名关系仍需后续独立表。

## Security, data and migration impact

- 七张新表全部启用 RLS，并先撤销 `anon` / `authenticated` 的默认权限，再按列和操作最小授权。
- `owner_user_id` 不授予读取权限；RLS 只决定行可见性，列级 grant 负责防止私有账号 ID 随可见内容泄漏。
- suspended/revoked Membership 即使仍有历史角色记录，也无法读取或管理内容。
- 核心内容不提供直接 DELETE 权限；当前以 `archived` 生命周期代替未获批准的永久删除策略。标签关联可以由所有者或管理员解除。

## Verification and review trigger

通过 Migration catalog/constraint/RLS 静态契约测试、Vitest 服务/Repository 测试以及可在一次性数据库执行的 SQL allow/deny 矩阵验证。

引入 Pen Name 公开署名、协作作者、Revision/Restore、公开访客阅读、软删除/永久删除、系列、Storage 或新的内容状态时必须复审本 ADR。

## Supersedes / superseded by

本 ADR 具体化 ADR-008、ADR-009 与 ADR-010，不替代其权限、标签治理和身份隔离原则。
