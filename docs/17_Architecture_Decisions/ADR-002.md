# ADR-002 — Why TipTap for Structured Editing

- Date: 2026-06-28
- Status: Accepted blueprint decision; implementation remains gated by Phase 0.6 approval
- Related .ai decisions: D-008, D-012

## Context

Works and Chapters need rich editing, validation, versioning, Diff, restore and safe rendering. Raw HTML is too unsafe and unstable as canonical content.

## Decision

Use schema-versioned TipTap JSON as canonical editable content; derive sanitized HTML and plain search text.

## Consequences

Requires shared schema/rendering in packages/editor and content migrations when the schema evolves; enables structured Diff and recovery.

## Alternatives rejected

- Leaving the concern implicit in implementation.
- Creating a parallel source of truth without documented ownership.
- Choosing short-term convenience over the project's security, archive and maintainability principles.

## Verification and review trigger

Review when its underlying product requirement changes, measured scale invalidates assumptions, a major provider/stack change is proposed, or an incident exposes a missing control.
